# KMP App P0 (Scaffold) + P1 (Data Layer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Kotlin Multiplatform app under `mobile/` (Android build runs; iOS host scaffolded but not run), and build a tested data layer that fetches, models, and caches the backend's `dist/` JSON — ending with a throwaway Android MapLibre spike that de-risks the map phase.

**Architecture:** A KMP + Compose Multiplatform project whose shared `commonMain` holds all logic. The data layer is three clean units: **serialization models** (kotlinx.serialization DTOs mirroring `dist/` JSON), a **network client** (Ktor, one method per endpoint), and a **repository** that combines network + a `SpotCache` interface with an offline-fallback rule. Persistence is SQLDelight behind the `SpotCache` interface, so repository logic is tested against an in-memory fake with no device or driver.

**Tech Stack:** Kotlin 2.1.0, Compose Multiplatform 1.7.3, Android Gradle Plugin 8.7.3 (min for `compileSdk 35`), Gradle 8.9, Ktor 3.0.1, kotlinx-serialization-json 1.7.3, kotlinx-coroutines 1.9.0, SQLDelight 2.0.2, JUnit4 + kotlin-test.

## Global Constraints

- **MVP is Android-only.** iOS is a *design* target: keep every platform-specific type behind `expect/actual`, keep the `iosApp/` host compiling, but do not run, test, or ship iOS in these phases.
- **No Android shortcut that blocks iOS.** All shared logic lives in `commonMain`; platform APIs (SQLite driver, HTTP engine) are `expect`/`actual` or injected, never referenced directly from `commonMain`.
- **Read base URL:** `https://maps.hitchwiki.org` (production `dist/` is the read API). Define once as `HitchwikiApi.BASE_URL`; never hardcode elsewhere.
- **Spot id derivation:** a spot id is `"${lat "%.5f"}_${lon "%.5f"}"` — five decimals, matching the backend's `generate_spot_id` and the `rides/by-spot/<id>.json` filename. Never invent another scheme.
- **Presence flags are true-or-absent.** In `spots.json` the keys `osm/cp/fuel/wiki/wikimap` appear only when true; a missing key means false. Model them as non-null `Boolean` with `= false` default.
- **Versions are a coherent baseline** from the JetBrains Compose Multiplatform ↔ Kotlin compatibility matrix. If Gradle fails to resolve them, advance the whole set together per that matrix — do not bump one in isolation.
- **All shared code compiles for `androidTarget()` and `iosArm64()/iosSimulatorArm64()`.** A change that breaks the iOS compile is a failure even though iOS is not run.
- **TDD, DRY, YAGNI, frequent commits.** Every code task is red → green → commit.

```kotlin
package org.hitchwiki.maps.util

/** Spot id = lat/lon each fixed to 5 decimals, joined by '_'. Mirrors the backend's
 *  generate_spot_id and the rides/by-spot/<id>.json filename. Uses a manual formatter
 *  because kotlin common has no String.format. */
fun spotId(lat: Double, lon: Double): String = "${fixed5(lat)}_${fixed5(lon)}"

private fun fixed5(v: Double): String {
    // Round half-up to 5 decimals, then render with exactly 5 fractional digits.
    val scaled = kotlin.math.round(v * 100000.0).toLong()
    val sign = if (scaled < 0) "-" else ""
    val abs = kotlin.math.abs(scaled)
    val whole = abs / 100000
    val frac = (abs % 100000).toString().padStart(5, '0')
    return "$sign$whole.$frac"
}
```

```kotlin
package org.hitchwiki.maps.data
import io.ktor.client.HttpClient
import io.ktor.client.call.body
import io.ktor.client.engine.HttpClientEngine

import org.hitchwiki.maps.model.Spot

fun defaultHttpClient(engine: HttpClientEngine): HttpClient =

    suspend fun spots(): List<Spot> = client.get("$baseUrl/spots.json").body()

    companion object { const val BASE_URL = "https://maps.hitchwiki.org" }
}
```

```kotlin
import org.hitchwiki.maps.model.Spot

// Persistence seam: the repository depends on this, not on SQLDelight, so its
// offline-fallback logic is testable with an in-memory fake.
interface SpotCache {
    suspend fun saveSpots(spots: List<Spot>)
```

`SpotRepository.kt`:
```kotlin
package org.hitchwiki.maps.data
import org.hitchwiki.maps.model.Spot

class SpotRepository(private val api: HitchwikiApi, private val cache: SpotCache) {
    /** Network-first: fetch, persist, return. On network failure fall back to the last
     *  cached copy (offline field use). Rethrow only when the cache is also empty. */
    suspend fun spots(forceRefresh: Boolean = false): List<Spot> {
        return try {
            val fresh = api.spots()
            cache.saveSpots(fresh)
            fresh
        } catch (e: Throwable) {
            val cached = cache.loadSpots()
            if (cached.isNotEmpty()) cached else throw e
        }
    }
}
```

`SqlDelightSpotCache.kt` (commonMain):
```kotlin
package org.hitchwiki.maps.data
import org.hitchwiki.maps.db.HitchwikiDb
import org.hitchwiki.maps.model.Spot

// Stores each Spot as its serialized JSON keyed by (lat, lon); a save replaces the whole
// set in one transaction so the cache always mirrors the latest spots.json.
class SqlDelightSpotCache(private val db: HitchwikiDb) : SpotCache {
    override suspend fun saveSpots(spots: List<Spot>) {
        db.hitchwikiDbQueries.transaction {
            db.hitchwikiDbQueries.deleteAll()
            for (s in spots) db.hitchwikiDbQueries.insert(s.lat, s.lon, appJson.encodeToString(s))
        }
    }
    override suspend fun loadSpots(): List<Spot> =
        db.hitchwikiDbQueries.selectAll().executeAsList().map { appJson.decodeFromString<Spot>(it) }
}
```

Note: the generated queries object name follows the `.sq` filename (`SpotCache.sq` → `spotCacheQueries`) or the database name; if the generated accessor differs, use the name SQLDelight generated (check `build/generated/.../HitchwikiDb.kt`). Adjust `db.<queries>` accordingly.
